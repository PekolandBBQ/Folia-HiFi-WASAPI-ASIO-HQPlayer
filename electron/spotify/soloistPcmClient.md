# Soloist main-only PCM client candidate

This local candidate is not registered in Electron IPC, a renderer provider or an App backend. It controls only the officially authenticated **current** Spotify track; it cannot select a different Folia search result. It requires the separately provisioned development appliance, fixed localhost SSH and its pinned host key. The guest owns Spotify credentials and authorization. This is not a distributable appliance or a verified lossless implementation.

`createSoloistPcmClient({keyPath, knownHostsPath})` uses the private SSH invoker. Tests inject `invoke(surface, operation, payload, {signal})` and `fetchImpl`. All operations use fixed remote script names and JSON stdin, at most 16 KiB input / 64 KiB output, a 12-second per-control deadline, hidden child processes and discarded stderr. User values and credentials are never placed into a shell command. The guest PCM URL and bearer remain private closures; returned values and stable errors cannot contain them.

- `prepare({session, trackId, positionMs=0, durationMs?, requestedQuality?})`: verify official authorization/current URI; stop the old PCM reader; pause and verify official paused state; seek and verify official paused position within 250 ms; prepare a new guest generation at the **reported** official position. Returns safe metadata and a `completed` Promise, still paused. It does not select songs or start playback.
- `openReadable(session, {signal?})`: one reader per generation. Fetches only the exact pinned localhost PCM endpoint with private authorization, rejects redirects or mismatched generation, strips and strictly validates the guest's 44-byte unknown-length WAV header, and yields frame-aligned raw `s32le` blocks of at most 64 KiB. It reads the next body block only as the consumer asks for it. Start consuming before `play` so the two-second guest queue can drain.
- `play(session)`: verify current official URI, valid login and active device before official play, then prove the same URI is playing. A command acknowledgement alone is insufficient.
- `pause(session)`: abort reader, close that guest generation, verify current official URI/login/active device before official pause and confirm official paused state. The completion kind is `paused`; this is not song EOF. Resume via new `prepare` or `seek`, then a new single reader and `play`.
- `seek(session, positionMs)`: replace the old generation using the same verified pause/seek/prepare transaction. Returns paused metadata, preserving the requested quality tier separately from unknown actual quality. The caller owns playback intent and starts the new reader/play explicitly.
- `status(session)`: sanitized PCM status, verifying auth and current generation. It is a low-frequency control check, not a high-frequency hardware playback clock.
- `close(session)` / `dispose()`: cancel local reads and close only the matching guest generation. It cannot stop a later unrelated guest session.

`completed.kind` distinguishes `eof`, `paused`, `seek`, `cancelled`, `closed`, `superseded`, `reader_disconnected` and `failed`. A normal HTTP EOF alone is insufficient: only guest `reason=eof`, exact bounded frame count and fully delivered frames count as finite song EOF. PCM header truncation, unaligned tail, oversized blocks, overflow, provider changes or generation replacement fail or cancel.

`preparedAudio` describes fixed PCM32 / 44.1 kHz / stereo. Original codec, source bit depth, bitrate, sample rate and actual quality remain `null` with `encodingVerified=false`. A requested lossless tier or a PCM32 output is not evidence of lossless source quality. Actual quality selection and original-source verification remain separate integration gates.

This candidate has strict current-track control and isolated tests. No App behavior changes or release claims are implied. Official arbitrary-track loading, runtime distribution/installation, browser/native/HQPlayer integration, hardware playback, account revocation wiring and verified quality tiers still need implementation and regressions before publication.

Every mutation also sends `expected_uri` to the guest, which checks official current URI/login/active device on the same WebSocket before dispatch. The SDK command has no compare-and-swap URI parameter, so an external controller can still change ownership in the remaining interval; this candidate does not claim atomic control of Spotify playback. Closing PCM never implicitly pauses a later unrelated official track.
