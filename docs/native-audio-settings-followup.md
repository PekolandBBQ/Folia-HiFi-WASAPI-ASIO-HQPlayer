# 原生音频设置人工验证修正

本轮接续 2026-09-29 最终报告，处理人工使用时发现的“组件未安装，选择设备无反应”以及依赖组件的设置仍可修改的问题。

## 当前行为

- 名称统一为“WASAPI及ASIO独占播放”，同步设置标题、侧栏标签及命令面板三种语言。
- 仅在 Windows 桌面环境、preload 确认当前进程架构受支持（当前为 x64），且原生 IPC 桥可用时显示模块、侧栏入口和相关命令。macOS、Linux、普通浏览器及不受支持的 Windows 架构隐藏这些入口。组件尚未安装的兼容 Windows 环境仍显示安装入口。
- 选择原生设备、修改自动回退、整数直通或音频链路前重新查询组件状态。不可用时不改变后端、设备、开关和播放状态，给出安装提示；设置面板可直接安装/更新，命令面板引导至对应设置区域。
- 无已批准安装源时说明原因，不显示无法执行的安装动作；安装失败显示翻译后的固定错误码，可重试。安装成功后重新选择即可生效。

## 为什么两项独立 PR 仍放在该模块内

PR 拆分是审查和合并边界，不能单凭拆分认定功能已经跨平台。以下依据当前实际实现，而非理论上能否移植。

| 功能 | 当前依赖 | 布局决定 |
| --- | --- | --- |
| 整数直通（实验性） | 宿主准备 PCM32，Windows 的 .NET/NAudio 引擎实现整数增益及 WASAPI/ASIO 输出。组件工程固定 `net8.0-windows`、`win-x64`；其他平台没有对应播放引擎 | 保留在 WASAPI及ASIO独占播放 模块下，仅兼容环境可用 |
| 显示音频链路 | React 界面及行格式化本身不依赖操作系统，但当前唯一实时遥测来源是 `NativeAudioTransport` 发布的原生引擎状态；浏览器输出被当前展示逻辑明确排除。macOS/Linux/Web 没有接入等价的数据采集 | 现阶段仍保留在同一模块下，避免单列一个无数据、无功能的入口 |

未来音频链路可以发展成独立的跨平台功能，但需先为 Web Audio 及其他后端增加可验证的音源/处理/输出信息，并区分真实测量、推断及未知项；不能只移动开关后将其标为支持其他系统。本轮不扩大音频后端功能范围。

代码依据：`electron/preload.cjs`、`src/services/nativeAudio/capabilities.ts`、`src/components/modal/settings/navigation/settingsAnchorModel.ts`、`src/components/modal/settings/navigation/settingsNavModel.ts`、`src/services/nativeAudio/NativeAudioTransport.ts`、`src/stores/useSignalPathStore.ts`、`src/components/audio/SignalPath.tsx`，以及独立组件的 `src/Folia.Audio.csproj` 和 `src/AudioEngine.cs`。

## 回归验证

新增覆盖：未安装/停用后的 WASAPI、ASIO 选择，三个依赖开关，安装失败/重试/成功，缓存状态失效，无批准发布，平台与架构可见性。回归同时检查拒绝操作时不暂停现有播放、不持久化无效选择。此处的平台覆盖是边界模拟和实际 Chromium 渲染验证，不冒称在 macOS/Linux 实机运行。

本补充不修改此前归档报告和压缩包的历史测试结论；新增交付件另行命名并记录哈希。

本轮结果：类型检查通过；7 个单测文件 139 项通过；Chromium 组件界面回归 17 项通过。包内完整 App 通过隔离 Electron 宿主加载实际 `app.asar` 的 `file:` 界面，5 项检查通过：中文入口和命令定位、整数直通缺失提示、音频链路缺失提示、实际设备列表在停用组件后选择 WASAPI 时弹出提示且不写入后端、界面离线安装与提示内重新安装。枚举确认了本机 XingCore ASIO 及三个 WASAPI 设备；本轮未启动音频输出，不干扰正在运行的人工版本。ASIO 缺失提示另由组件界面测试覆盖。

交付核验：185 个界面文件与本轮构建逐字节一致；8,354 个非界面 ASAR 文件与此前已验证运行时一致。原包中 12 个已裁剪的其他平台解包文件条目也保持原状。完整 App 检查是隔离宿主加载包内代码，未将其记为新 EXE 的独立首次启动测试。此前全量 4023 项单测、275 项 UI 和音频发行件检查属于基线证据，本轮未重复全跑。

打包前于北京时间 2026-09-29 再查官方 API：最新正式版仍为 v0.7.9；main 已到 `481805873a0b04ca6277dd21c0968ab1e1c4ab02`，相对此前基线有 3 个提交，涉及 Folium 文档和 Grid3DSlider 及其单测。没有修改本轮音频设置路径；本交付仍以此前通过验证的 v0.7.9 集成为基础，不冒称已整合并全量复测最新 main。

## 人工使用

完整解压名称含 `settings-fix` 的新 ZIP。先自行关闭旧的 `Folia Native Validation.exe`，再运行新目录内同名程序；继续使用 `%APPDATA%\FoliaNativeManual-20260929` 的已有人工验证配置。旧包不包含本轮修正。

在“设置 → 播放 → WASAPI及ASIO独占播放”先选浏览器后端，再停用组件，分别选择列表内 WASAPI/ASIO 和三个依赖开关：应显示安装提示，取消后设置保持不变。从提示安装后重新选择应生效。整数直通和显示音频链路仍在同一模块内。其他平台入口的验证是能力边界模拟，不是 macOS/Linux 实机测试。

本轮补丁位于集成分支；A/B/C 已归档审查快照未被悄然改写。后续更新独立 PR 时须将通用组件门禁分别落入 A，再将整数和链路开关的门禁落入 B/C，并分别复测，不能用本轮集成测试替代这些分支测试。
