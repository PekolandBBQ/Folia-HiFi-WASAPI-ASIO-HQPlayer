# 独立发行版验证报告

## 0.7.12 / 两个独立音频组件 0.1.2（2026-10-02）

本次合并上游稳定标签 `v0.7.12`，应用与上游同版，专版标签为 `hifi-v0.7.12`。改动见 [发行说明](releases/0.7.12.md)。HQPlayer 与 WASAPI/ASIO 组件均继续使用已发布的独立 0.1.2，窗口显隐属于 Windows 宿主功能，不修改 Control API 组件。

- 全新目录完整 `npm ci`，未跳过安装脚本；类型检查及全量单测 **482 文件通过，4827 项通过，2 项显式跳过**。sync-server 完整安装、构建和 SQLite 内存数据库读写通过。
- 全量界面回归覆盖 **322 项**，包括上游新增界面、明暗主题、毛玻璃表面、紧凑布局、抽屉收缩、详情进入/退出、预读缓存、统一开关、歌曲提示避让、播放/暂停切换与音量保持。最初发现歌词样式计数仍写 13，已按新增 Lumière 更新为 14；原始失败与复测记录保留。
- 本地文件、网易云、QQ 音乐分别验证前台与静默启动，**六组实际播放场景通过**，使用 0.7.12 打包程序、HQPlayer Desktop 6 和 XingCore USB DAC。QQ 静默最终场景在 NSIS 安装版上执行。
- 两个在线平台均通过真实 Omni 搜索与取流，验证冷启动、重复播放、切歌、暂停/播放时应用当前 DSP、窗口显示/隐藏、HQPlayer 到浏览器/WASAPI/ASIO 及 WASAPI/ASIO 返回 HQPlayer。续播未补按播放；位置断言使用切换前检查点，实例数量和窗口可见性均实际读取。
- 浮窗显示/隐藏保留相同进程及播放状态；切换离开 HQPlayer 后实例数为零。组件 UI 同时覆盖已有实例连接确认及拒绝后的回退。
- 打包程序的 **274 个运行文件**与构建产物逐项一致；HQPlayer ZIP 保持官方 0.1.2 哈希。NSIS 安装成功并与未安装载荷逐项比对；最终分发校验和与程序一致性记录附于 Release。
- GitHub 的上游类型/单测、sync-server 构建以及 Windows HiFi 设置回归门槛保留，合并提交均通过；最终发布提交另附对应检查结果。

### 时间与证据边界

本轮流媒体冷启动至进度超过两秒，网易云约 **13.3–13.5 秒**，QQ 约 **14.8–15.6 秒**；重复及切歌约 **5.8–6.8 秒**。本地加载及启动约 **9.4–9.5 秒**。这些是当前设备、曲目和已有配置下的观测，不是空缓存首次安装基准，也不保证所有音源的等待时间。下载、解码与 DSP/设备准备仍分别展示进度。

网易云两轮的底层日志记录了退出 DSD 后首次打开 PCM 端点的 `DEVICE_UNAVAILABLE / 0x88890004`。现有有界重试随后成功，播放保持检查点，界面没有收到失败事件；其中一次设备枚举也在下一次查询恢复。不能将测试总体通过描述成底层从未报错，更不能将其统归为缓存问题。

QQ 静默第一次搜索三组关键词均返回零首，尚未进入播放；随后取得音源的一轮被安装验证关闭同名程序而中断，最后在安装版上完整重跑通过。两次失败及最终通过均保留。早期 0.7.9 候选的设备枚举失败另作历史证据，不混入 0.7.12 通过计数。

合并过程中修正了测试桩缺少新增窗口接口、测试服务器缺少模拟 API 地址，以及构建分块变化导致人工脚本导入不存在文件的问题。UI 搜索/导入模拟数据中的收藏列表与不可克隆文件句柄警告不等同于实机播放错误；原始日志保留。HQPlayer 整秒定位、DSP 预热及其他硬件的限制见发行说明；本轮没有重新做主观音质比较。

## 本次找到并处理的问题

- XML 库原先只属于开发依赖，实际 ASAR 中缺失，导致首个打包候选无法启动。已迁入生产依赖并显式检查打包输入，最终 EXE 启动通过。保留初次失败日志。
- 首次完整播放复测中，HQPlayer 第二首曲目的暂停后定位断言失败。排查发现命令和轮询状态会交错；我补上有期限的定位状态确认，拒绝旧位置回报覆盖正在确认的目标位置，并补测这一路径。后续专项及完整发行件复测均通过。初次失败截图、结果和控制接口轨迹保留；初次失败没有完整逐包轨迹，因此不把该次具体回跳原因描述为唯一确定的结论。
- HQPlayer 增益现在分开保存余量与合并音量，避免正 ReplayGain 触及 0 dB 上限后，或旧音量状态迟到时，反向污染余量。
- 用户原始 `.audio` 文件不会因扩展名识别而被改名；只处理会话拥有的副本。旧请求取消后，晚到解码结果不能再次加载。
- HQPlayer 不再列入 WASAPI/ASIO 设备下拉框，使用同级独立设置和导航。缺少原生组件不会阻止 HQPlayer；闲置 helper 的故障也不会被错误归到当前 HQPlayer 会话。
