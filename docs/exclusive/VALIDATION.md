- 界面回归共 **323 项**，覆盖明暗主题、毛玻璃、紧凑布局、抽屉动画、详情进出、预读缓存、统一开关、歌曲提示避让、输出续播、音量保持和准备失败状态。

### 冷启动失败的修复与复测

0.1.2 候选曾实测出现 `HQPlayer PlaylistAdd failed: Error`：下载约 457 毫秒已完成，检查约 488 毫秒完成，至加入歌曲约 8.4 秒，随后明确拒绝；界面却长期停在“原生输出准备中”。这是本次捕获的失败位置，不能归因为下载未完成或笼统的首次缓存问题。相同旧组件接着八次冷启动通过，证明问题间歇出现，不构成修复证据。

0.1.3 对冷连接的明确 `PlaylistAdd Error` 采用最多六次尝试、250/500/1000/1500/2500 毫秒退避；首轮成功不增加等待，认证失败和结果不明确的超时不重试。失败后仍保留首次加载恢复机会，并记录每次加入歌曲的结果。宿主在最终失败时明确显示“输出准备失败”和错误详情，再次播放会清除旧失败状态。真实六组回归已全部重测通过；额外八次前台/静默交替冷启动也全部通过（各四次，约 14.1–15.3 秒），诊断显示每次均首轮接受歌曲。

HQPlayer 内部为什么在该时刻拒绝文件，外部接口没有给出更细原因；冷启动就绪时序是推测，不能写成已证明的内部根因。新的有界恢复已验证，但不承诺所有机器上的间歇性问题已绝对消失。

### 设备与证据边界

退出 DSD 后，XingCore 端点会短暂重新枚举；部分轮次记录底层 `DEVICE_UNAVAILABLE / 0x88890004`。限定于 HQPlayer 输出交接的重试随后成功，界面未收到失败事件，歌曲与位置保持。保留这些底层日志，不将测试通过描述成底层从未报错。

此前 QQ 搜索零首、验证安装关闭了正在运行的测试程序、构建分块名称变化等失败，也已分别重新取流或修正测试环境后重测通过。UI 模拟数据的收藏列表和不可克隆文件句柄警告与实机播放错误分别记录。

以上时间来自当前曲目、设备和已有配置，并非空缓存首次安装基准。下载、检查/解码、输出连接与 DSP 准备分别显示进度；HQPlayer 整秒定位、DSP 预热以及输入输出硬件仍在 Desktop 内配置的限制见 [发行说明](releases/0.7.12.md)。没有将状态验证当作主观音质测试。

## 本次找到并处理的问题

- XML 库原先只属于开发依赖，实际 ASAR 中缺失，导致首个打包候选无法启动。已迁入生产依赖并显式检查打包输入，最终 EXE 启动通过。保留初次失败日志。
- 首次完整播放复测中，HQPlayer 第二首曲目的暂停后定位断言失败。排查发现命令和轮询状态会交错；我补上有期限的定位状态确认，拒绝旧位置回报覆盖正在确认的目标位置，并补测这一路径。后续专项及完整发行件复测均通过。初次失败截图、结果和控制接口轨迹保留；初次失败没有完整逐包轨迹，因此不把该次具体回跳原因描述为唯一确定的结论。
- HQPlayer 增益现在分开保存余量与合并音量，避免正 ReplayGain 触及 0 dB 上限后，或旧音量状态迟到时，反向污染余量。
- 用户原始 `.audio` 文件不会因扩展名识别而被改名；只处理会话拥有的副本。旧请求取消后，晚到解码结果不能再次加载。
- HQPlayer 不再列入 WASAPI/ASIO 设备下拉框，使用同级独立设置和导航。缺少原生组件不会阻止 HQPlayer；闲置 helper 的故障也不会被错误归到当前 HQPlayer 会话。
