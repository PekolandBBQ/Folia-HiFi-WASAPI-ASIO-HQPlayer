# r2 HQPlayer 供数与控制恢复（2026-10-15，最小功能验收完成）

本轮仍使用 0.7.19 / r2，不更改 release 标题和页面。本轮最小功能验收完成；按 PR、Issue 回报、同一 release 覆盖的顺序发布。

## 用户日志与定位

两个用户日志记录了 BOOTSTRAP_IDENTITY_UNCONFIRMED、PREPARED_TARGET_ACTIVITY_EXPIRED、Pause/State 拒绝、Play/State 响应超时，以及后续 leaveProvider 重复 HQPLAYER_COMMAND_REJECTED。旧日志缺少完整的底层启动详情，不能断言所有远端首次启动失败都属于同一原因。

- Wrapper 冷启动选曲预算为 30 秒，但选曲后的音频进程确认仅使用默认 4 秒。改为沿用本次选择预算，就绪立即退出，不重复选曲或调整 Spotify 音量。
- 准备活动确认在原生扫描前后重复做整套策略检查，并以取证前的总耗时判断证据过期。保留原生扫描内前后进程、端点和路由核对，去除外层重复扫描，以证据实际年龄判定过期。组件升级为 route dev.29，capture.11 不变。
- 当前歌曲 DSP 应用先 Stop，再重开流时重复 Pause/Stop，可能被已停止的 HQPlayer 拒绝。记录成功 Stop；收到新的运行状态则撤销该记录。
- Stop 被拒绝后，仅当新的 State 明确返回停止状态，才确认释放。断连时重连控制接口，不另开实例；未知状态继续保留具体错误和可重试的旧会话。
- 控制回复没有请求编号。命令超时后丢弃旧连接、等待者和残留接收数据，避免迟到 ACK 匹配后续同名命令。
- 组件错误详情通过 RPC 保留，避免只剩笼统拒绝码。正常 HQPlayer 路径也可在私有诊断开关下记录管道供数和存量，无额外启动延迟。
- 组件可用性检查失败、尚未启动过 worker 时，shutdown 不再尝试启动不可用组件，允许退出 HQPlayer 后更新。启动过 worker 的会话仍保留真实释放确认。

## 最小链路与证据边界

模拟链路使用实际生产组件的命名管道、PCM 队列、本机 HTTP，输入带连续编号的 44.1 kHz 双声道 32 位 PCM。消费者时钟为模拟，不能当成实际 HQPlayer 出声。

- 350 ms 预缓冲：实际积累 350–360 ms；注入 200 ms 生产停顿后，最小剩余约 106 ms，编号无丢失或乱序。
- 5000 ms 预缓冲：实际积累约 5010 ms，最小剩余约 4975 ms。不是纯计时等待。
- 相同 poly-sinc-gauss-xl / ASDM7EC-fast / SDM 参数下，实际 HQPlayer 接收 24 秒合成输入，位置推进到 24 秒，没有报告缓冲等待。
- 完整 Folia 的 Spotify 首播成功。第一段约 159 秒、350 ms 设置、额外延迟 0：管道最大间隔 24 ms，稳定段未播放存量最低约 2523 ms，没有缓冲等待事件。
- 当前歌曲改用 FIR 仅用于验证 DSP 应用，HQPlayer 前端确认 FIR，播放继续；随后恢复 poly-sinc-gauss-xl。自动下一首成功。低负载 DSP 的结果不用于证明原滤波无爆音。
- 关闭第一轮候选窗口后，路由明确报告 exactOriginalRolesRestored=true、globalDefaultsWritten=false。随后停止已无窗口的本轮候选进程，以启动下一装配；此操作不冒称应用完整退出菜单验收。
- 最终 dev.29 / preview.7 候选：原滤波与整形器下 156 个稳定段样本，最大管道间隔 24 ms、最小未播放存量 2480 ms、缓冲等待事件 0。未增加启动延迟。
- 最终候选“下一首生效”改为 DSD5，HQPlayer 前端确认并继续播放；“应用到当前歌曲”恢复 ASDM7EC-fast，成功回报，随后自然切歌继续。改变整形器的区间仅验证功能，不用于原设置下的供数结论。
- 最终候选关闭后在 1792045881637 确认原路由恢复、未写全局默认，1792045881664 确认 quit-restoration-complete。
- 手动下一首时保留一次旧请求 CANCELLED（1792045444418）；后续释放和新歌曲播放成功，不把取消记录当作日志零错误。
- 两次未发布 preview.7 候选内容不同造成一次 COMPONENT_INCOMPATIBLE；经 Folia 自身退出 HQ 输出、安装/更新组件后恢复。未将该本地候选旧摘要加入公开兼容清单，也未覆盖原组件目录。

采集帧数、HQPlayer 进度与 buffering=false 均不能代替硬件输出的听感或波形测量。当前未复现曲中供数耗尽，不能宣称爆音根因已修复。曲末停止供数、暂停和关闭阶段不计入曲中抖动。

- 渲染准备策略回归 8 项通过，类型检查、桌面 renderer 构建通过。最终装配首次播放正确显示已有 HQPlayer 确认，接受后自动重试并播放，无须再点播放。

- 1792049131871 收到最终 HQPlayer 释放确认；1792049131890 quit-restoration-complete。原配置和备份保留。
- 启动时 Spotify 状态查询存在 SPOTIFY_INSTANCE_CHANGED / unavailable，保留于记录；未阻断本轮网易云。已有 HQPlayer 确认码属于已完成的交互流程，不能当作未处理播放失败。
