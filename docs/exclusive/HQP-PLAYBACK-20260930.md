# HQPlayer 播放修复 0.1.1

主程序本地测试版 `0.7.9-preview.20260930.3`；HQPlayer 独立组件 `0.1.1`；WASAPI/ASIO 组件保持 `0.1.2`。

旧版真实文件播放复现 `NATIVE_REQUEST_FAILED: An object could not be cloned`。`prepare` 误把含套接字的控制协议对象返回到 Electron utilityProcess 跨进程边界；现在仅返回 `{ok:true}`。这次停在连接准备的直接原因不是缓存。

切换离开 HQPlayer 时显式关闭全部本机 Desktop 实例，并等待退出后再提交新的输出选择；正常退出 Folia 仍只清理由 Folia 启动的实例。拒绝连接已打开的 HQPlayer 不会关闭该未连接实例。过期歌曲命令按取消处理，避免切换时误报原生操作失败。

实机测试还复现 XingCore 从 DSD 输出交接到 WASAPI 时的 `0x88890004`：进程退出并不保证驱动的 PCM 端点立即恢复。现在先正常关闭 HQPlayer（超时才强制终止），重建空闲原生驱动进程，并仅对这一交接阶段的设备失效进行最多三次有界重试（300/900/1800 ms）；不切换设备、不降级输出模式，取消歌曲时立即停止恢复。真实测试触发一次失效后恢复成功。

浮窗按钮显示“HQPlayer设置”；音频链路移除等宽字体覆盖；四项设置复用 Folia 的 CustomSelect；SDM 采样率以 `48k x1024` 等 HQPlayer 单位显示。设置页可保存默认升频模式、滤波器、整形器和目标采样率；新歌曲加载前应用，浮窗的单次设置优先。默认值留空时保留 HQPlayer 当前配置。

兼容模式、静默启动、记忆增益和音频链路等布尔项统一为 Folia 滑动开关。输入/输出硬件设备选择仍由 HQPlayer Desktop 完成，当前接入的官方控制接口不提供设备切换，界面已说明此限制。

新包包含旧组件的固定哈希及新组件，在本地专版启动时升级已知的旧版；用户明确停用的组件不会被重新开启。上游普通入口没有自动升级策略变更，没有发布到 GitHub。

本轮核心验证：真实 FLAC 冷启动加载约 7.8 秒，HQPlayer 回报播放位置前进、45.1584 MHz SDM（DSD1024）及约 1.05 秒输出延迟；关闭后实例数为零。117 项相关主程序测试、22 项组件测试和 6 项组件界面测试通过。真实流媒体与最终打包验证结果随交付报告单独保存；本地 HTTP 测试不能替代网易云音乐实测。

最终网易云测试通过 Folia Omni 解析真实歌曲链接，覆盖首次加载、重复播放、下一首及 HQPlayer → 浏览器 / WASAPI / ASIO。首次阶段 13.07 秒，重复 5.74 秒，换曲 5.71 秒；这些计时包含等待实际播放位置超过 2 秒，不是首个声音延迟。HQPlayer 输出 45.1584 MHz SDM，WASAPI/ASIO 输出 44.1 kHz；每次退出 HQPlayer 后实例数均为零。第二首受未登录权限限制为 30 秒试听，不把它当作全曲权限验证。后续音频改动的必测流程已加入真实网易云回归要求。

收尾验证：新增恢复逻辑后，105 项原生音频单元测试与 22 项 HQPlayer 组件测试通过。完整 npm ci 已分别在主程序、HQPlayer 组件和 sync-server 执行；sync-server 的原生 SQLite 已编译并完成读写验证。保留 npm 的项目安装脚本策略，未使用 ignore-scripts 冒充完整安装；sync-server 的既有审计结果另存。
