# Folia 本地播放准备与 HQPlayer 测试版

版本：0.7.9-preview.20260930。仅本地构建，未提交、推送或发布到 GitHub。
独立程序名 Folia-HiFi-Preview，独立配置目录 `%APPDATA%/Folia HiFi Preview`，不迁移正式版配置。

## 已实现

- 左下角显示缓存检查、音源解析、下载、上传、解码、校验、HQPlayer 连接、加载、缓冲阶段；下载长度已知时显示真实字节进度，否则显示不定进度与耗时。换歌、取消、失败会结束对应请求的显示。
- HQPlayer 冷启动与音频下载重叠执行，正常 HQPlayer 播放不再预先执行不需要的 FFmpeg 校验，缓存可用的安装发现结果。
- 兼容模式默认关闭；严格解码识别到损坏数据时，提供仅当前歌曲、后续保持开启和取消。后台预加载不弹出确认。兼容恢复可能跳过损坏帧，转码恢复结果仍严格校验。
- HQPlayer 音频链路旁提供模式、滤波器、整形器/调制器、目标采样率设置，可选择当前歌曲或下一首生效。当前歌曲应用会短暂停止并恢复位置；下一首按歌曲身份生效，同曲重试不提前消耗设置。
- 通过 HQPlayer 实际能力列表生成 PCM/SDM 选项；读取另一模式的列表仅在停止状态进行，并恢复原参数。播放中缺少另一模式的列表时，界面提示先在 HQPlayer 停止并刷新。
- 检测现有 HQPlayer 实例时先确认；选择“是”只连接已有进程，选择“否”恢复先前输出设置。多个现有实例直接报错。启动前在 Windows 命名互斥锁内再次检查，避免 Folia 重复启动。
- 后台静默开启默认关闭，新启动的 HQPlayer 默认使用正常前台窗口；已由用户打开的实例不会被隐藏或由 Folia 退出时关闭。

## 尚未实现的设备切换

HQPlayer Desktop 的公开控制 SDK 未提供输入/输出硬件设备选择命令。浮层目前说明输入来自 Folia 文件/流媒体，硬件设备仍需在 HQPlayer Desktop 选择；没有制作不能生效的设备下拉框。
参考：[Signalyst 官方控制 SDK](https://www.signalyst.eu/bins/hqp-control-601-src.zip)。

## 延迟定位与测试边界

代码确认原流程依次执行完整音频下载和 HQPlayer 冷启动，且在进入 HQPlayer 路径前有不必要的 FFmpeg 发现/校验。这些等待会累加。未发现固定 30 秒的首次缓存建库计时器；尚未复现用户实际音乐服务、曲目与 DAC 上的 30 秒等待，不能断言缓存是唯一原因。

最终空闲构建后对照：新建 Folia 临时配置、同一个 2 秒静音 PCM WAV、localhost 下载限时约 3 秒、HQPlayer 每次冷启动、不发送 Play。基线提交 `3f22a6a3360569eb7855c2a3144d8dc5abc671b6` 准备时间 10.73 秒，最终改动 7.79 秒，单次对照缩短约 27%。这是进入可播放状态的受控测试，不是实际流媒体或 DAC 出声延迟保证。

## 建议试用顺序

1. 保持兼容模式与后台静默开启均关闭，第一次播放原先卡顿的流媒体曲目，观察左下角耗时最长的阶段。
2. 关闭 Folia 启动的 HQPlayer 后，手动打开 HQPlayer，再切换 Folia 到 HQPlayer 输出，分别测试“否”和“是”。
3. 在 HQPlayer 控制浮层选择当前模式的参数，分别验证“当前歌曲”和“下一首歌曲”，观察歌曲位置与 HQPlayer 本体参数。
4. 用原先严格解码报错的歌曲验证兼容选择。仅当前歌曲不改变全局开关，后续保持开启会保存偏好。
