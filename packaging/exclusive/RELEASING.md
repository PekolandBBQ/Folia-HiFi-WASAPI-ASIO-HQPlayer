# 专版双源发行附件保留规则

维护者于 2026-10-19 明确授权每次 Gitee 发布均执行以下规则。

1. GitHub 保留完整历史发行件；Gitee 只保留最新正式版的大型安装包和便携包附件。
2. 发布前确认旧版完整 EXE / ZIP 在 GitHub 仍可下载，再删除 Gitee 旧版的 EXE、ZIP 及其分片。不可删除发行说明、标签、源码历史、本机配置或组件备份。
3. Gitee 旧版说明添加 GitHub 对应版本的下载链接。小型说明文件和更新清单可保留；应用更新接口应指向最新完整正式发行版。
4. GitHub 和 Gitee 使用同一次构建；Gitee 按既有清单分片。待全部预期附件上传完毕、清单名称和大小与附件列表相符后，再设为正式版，避免暴露不完整更新。
5. 只清理目标 fork 的 Gitee 附件，不操作上游仓库。上传失败时保留未完成发行版为预发行状态，按已上传附件续传，不重复删除或覆盖已有备份。

用户无需为每次旧包清理重新确认；若扩大为删除说明、标签、源码或 GitHub 历史包，则不在上述授权范围。
